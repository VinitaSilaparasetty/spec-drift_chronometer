## Not committed — what else you will see when you run it

Start the stack with `DEMO_MODE=true ./dev.sh` and open `http://localhost:3000`.

**Justification Gate, active (critical drift).** After roughly 45 seconds the
drift crosses 0.0075. The header gains a pulsing red **JUSTIFICATION GATE
ACTIVE** button, the Drift Index card turns red, System Health shows
**CRITICAL_DRIFT** and Spec Compliance shows **BREACH**. The modal opens with the
metric row, the spec reference, an empty justification textarea and an amber
**Submit to Warden Agent** button.

**Warden analysing.** On submit the button becomes "Warden Analyzing..." with a
pulsing amber dot and the line "Invoking amazon.nova-pro-v1:0 in eu-central-1 for
reasoning analysis...". In `DEMO_MODE` this resolves in about a second; against a
real backend it takes roughly as long as the model does.

**Audit trail.** **Download Audit** saves `spec_drift_audit_trail.txt`, an
ASCII-framed report carrying the timestamp, mode, drift index, threshold, gate
status, the Article 12 and 14 compliance lines, the sovereign region and the
justification record. A sample is in the main README.

## A note on DEMO_MODE

Both committed screenshots are demo-mode captures, and the hosted demo runs with
`DEMO_MODE=true`. For screenshots of live model inference, run locally against a
real backend:

```bash
DEMO_MODE=false WARDEN_LLM=mistral MISTRAL_API_KEY=... ./dev.sh
```

Empirical results from real backends — Mistral, Llama via Hugging Face — are in
[`test_research/results/`](../test_research/results/).
